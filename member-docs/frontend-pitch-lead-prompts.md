## File 1 of 8: Project skeleton — `App.jsx`, `main.jsx`, `index.css`, `src/api/client.js`

**Build order note:** P1, your first real file beyond the Vite scaffold itself. Depends on nothing except the scaffold existing.

**Files to upload alongside this prompt:** none required for the skeleton itself.

**Prompt:**

```
I'm building the frontend shell for an image-tampering-detection web app
— Vite + React + Tailwind (v4, via @tailwindcss/vite, already configured).
The app's core flow: a user uploads an image, it's sent to a FastAPI
backend's POST /api/analyze endpoint, and the result (a verdict plus
per-layer forensic scores and a heatmap) is displayed.

Write:

1. src/main.jsx — standard Vite React entrypoint, nothing unusual.

2. src/App.jsx — a top-level component that renders a simple page
   layout: a header with the project name, and a main content area that
   will eventually hold an uploader on one side and results on the
   other (I'll build those as separate components next — for now, just
   render clean placeholder text in each area so the layout and spacing
   can be judged visually).

3. src/index.css — the Tailwind import line (@import "tailwindcss";)
   plus any minimal global resets (box-sizing, font family — pick a
   clean, modern system font stack) needed before component-level
   styling takes over.

4. src/api/client.js — a fetch wrapper module exporting a single async
   function `analyzeImage(file)` that:
   - Reads an API base URL from import.meta.env.VITE_API_BASE_URL.
   - Builds a FormData object with the file under the field name
     "image" and POSTs it to `${baseUrl}/api/analyze`.
   - Parses and returns the JSON response on success.
   - Throws a clear Error with a useful message on any non-2xx response
     or network failure, so calling code can catch it and show a
     meaningful error state rather than an unhandled promise rejection.
   - For now, also export a boolean-controlled mock mode: a constant
     USE_MOCK (default true) that, when true, instead imports and
     returns src/data/mockResult.json after a short artificial delay
     (e.g. 800ms, via a Promise + setTimeout) so the loading state is
     visually testable before the real backend exists. Make switching
     USE_MOCK to false the ONLY change needed to go live later — don't
     scatter the mock/live decision across multiple files.

Use plain modern React (hooks, functional components only, no class
components). Tailwind utility classes for all styling — no separate CSS
files beyond index.css. Keep this clean and minimal; it's a skeleton,
not the final design.
```

```

analyzeImage(file) function. Write two files:

1. src/components/Uploader.jsx — a file upload component:
   - A styled drop zone using native HTML5 drag-and-drop events (no

   { status, result, error, analyze } where:
   - status is one of "idle" | "loading" | "success" | "error".
   - analyze(file) is an async function that calls the attached
     analyzeImage(file), setting status to "loading" immediately, then
     "success" with the result or "error" with a message, covering both
     thrown errors from analyzeImage and any unexpected exceptions.
   - result holds the parsed AnalysisResult once status is "success".
   - error holds a human-readable string once status is "error" — not
     a raw Error object or stack trace.

needed for this). Tailwind for Uploader.jsx's styling. Full functional

```

## File 5 of 8: `ImageCompare.jsx` (heatmap + opacity slider)

**Build order note:** E2/E3. Depends on Forensics Lead's `overlay.py` eventually providing a real base64 heatmap PNG — build against the mock's placeholder image first.

**Files to upload alongside this prompt:** `mockResult.json` (to see the exact field name/format the heatmap PNG is returned under).

**Prompt:**

```
I have a sample API response (attached) including a base64-encoded PNG
heatmap image under some field (check the attached JSON for the exact
field name — likely something like heatmap_png_b64 inside one of the
per_layer entries, or possibly a top-level field; use whatever's
actually there). Write src/components/ImageCompare.jsx:

1. Displays the original uploaded image and the heatmap PNG stacked
   exactly on top of each other (absolute positioning, same dimensions)
   — the heatmap is a separate <img> element layered over the original,
   NOT pre-blended by the backend.
2. A slider (a plain HTML range input, Tailwind-styled) controls the
   heatmap layer's opacity via inline style (style={{opacity: value}}),
   updated via React state — this should feel instant, with zero network
   calls as the slider moves, since the blending is purely a CSS/client-
   side concern.
3. Decode the base64 PNG string into a valid <img> src using a data URI
   (src={`data:image/png;base64,${heatmapB64}`}) — don't try to decode it
   into a Blob/ObjectURL unless there's a specific reason to, the data
   URI approach is simpler and sufficient here.
4. Handle the case where no heatmap is available for a given result
   (e.g. all layers skipped, or offline mode) by showing just the
   original image with a small "no heatmap available" note, rather than
   a broken image icon.
5. Default the slider to a reasonable starting opacity (e.g. 0.5) so the
   comparison is visible immediately without requiring interaction.

Tailwind for styling. Functional component, plain useState for the
opacity value.
```
